RAG System using LLMs

Development of Retrieval-Augmented Generation (RAG) systems capable of answering questions about parliamentary documents through lexical, semantic, and hybrid retrieval combined with large language models.

GitHub

Problem

Large Language Models can generate incorrect answers when they do not have access to the appropriate context. To address this problem, the system first retrieves the most relevant document chunks from the corpus and provides them as context before generating the answer.

Architecture

General architecture of the RAG system, from information retrieval to answer generation using the language model.

Technologies

  • Python
  • Hugging Face Transformers
  • Mistral-7B
  • OpenSearch
  • Sentence Transformers
  • Docker
  • PyTorch

How It Works

The system follows a RAG pipeline in which information retrieval is performed before answer generation. This allows the language model to access context obtained from parliamentary documents before answering the user's query.

Data Preparation and Indexing

Parliamentary documents are processed and divided into chunks of up to 300 tokens. Each chunk preserves textual information and relevant metadata to facilitate subsequent retrieval.

Information Retrieval

Given a question, the system retrieves the most relevant chunks using different strategies: BM25, embedding-based retrieval, OpenSearch hybrid search, and Reciprocal Rank Fusion (RRF).

Context Construction

The retrieved chunks and their metadata are concatenated to construct the context provided to the language model together with the original question.

Answer Generation

The retrieved context is included in a prompt together with the user's query. Mistral-7B-Instruct uses this information to generate an answer based on the retrieved content.

Evaluation

The system is evaluated from both the retrieval and generation perspectives. Retrieval is evaluated using HitRate@K, Precision@K, and Recall@K, while answer quality is analyzed using Context Relevance, Faithfulness, and Answer Relevance.

Results

The system was evaluated on a dataset of 40 questions, analyzing both information retrieval quality and the quality of the generated answers.

Retrieval Evaluation

Four retrieval strategies were compared: BM25, embeddings, OpenSearch hybrid search, and Reciprocal Rank Fusion (RRF).

Results with k = 3

System HitRate@3 Precision@3 Recall@3
BM25 0.700 0.267 0.388
Embeddings 0.625 0.250 0.333
OpenSearch Hybrid 0.575 0.192 0.283
RRF Hybrid 0.725 0.292 0.396

Results with k = 5

System HitRate@5 Precision@5 Recall@5
BM25 0.775 0.190 0.446
Embeddings 0.725 0.175 0.412
OpenSearch Hybrid 0.700 0.267 0.387
RRF Hybrid 0.775 0.200 0.458
Conclusion: RRF achieves the best overall retrieval performance, particularly in Recall@5 (0.458), while sharing the best HitRate@5 (0.775) with BM25.

LLM-as-a-Judge Evaluation

The quality of the generated answers was evaluated using a language model as a judge, employing three metrics on a scale from 1 to 5: Context Relevance, Faithfulness, and Answer Relevance.

System Context Relevance Faithfulness Answer Relevance
BM25 3.55 3.58 3.55
Embeddings 4.90 4.90 4.90
OpenSearch Hybrid 4.90 4.90 4.90
RRF Hybrid 4.65 4.62 4.67

External Judge Evaluation

As an additional evaluation, an external assessment was performed on the RRF hybrid system to analyze the quality of the retrieved context and the generated answers.

System Context Relevance Faithfulness Answer Relevance
RRF Hybrid 3.35 2.75 3.05

Conclusions

  • RRF achieves the best overall retrieval performance. The combination of BM25 and semantic retrieval through Reciprocal Rank Fusion achieves the best overall results, with a HitRate@3 of 0.725 and a Recall@5 of 0.458.
  • Retrieval quality is fundamental. The results show that the performance of the RAG system largely depends on the ability of the retrieval module to provide the model with relevant context.
  • LLM-as-a-Judge self-evaluation presents an optimistic bias. Using the same generative model as the judge produces systematically high scores, even when retrieval metrics indicate that no relevant information has been retrieved. This highlights a tendency to prioritize superficial linguistic coherence over the factual faithfulness of the answers.
  • External evaluation provides a more demanding perspective. The external judge obtained scores of 3.35 for Context Relevance, 2.75 for Faithfulness, and 3.05 for Answer Relevance for RRF, showing that there is still room for improvement in the final generation stage.
  • The RAG system can ground answers in information retrieved from the document corpus. The use of external context reduces the model's dependence on its internal knowledge and improves the generation of answers related to the parliamentary domain.
